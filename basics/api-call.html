API 호출 실전 — 공공데이터포털로 처음부터 끝까지

API 역사에서 "컴퓨터끼리 어떻게 대화하나"를 봤다면, 이 장은 실제로 한 번 불러서 데이터를 끝까지 모아 저장하기까지 갑니다. 예제는 공공데이터포털(data.go.kr)의 특일 정보(공휴일) API입니다. 키 발급, 주소 만들기, 인증키 인코딩 함정, 응답 구조, 에러 두 층, 페이지 넘기기, 재시도, 저장까지 다룹니다. 그다음 광고 매체 API는 무엇이 다른지 비교합니다.

읽기 약 40분 · 손으로 해 보기 4개 (키 없이 3개 + 내 키로 1개) · 퀴즈 5문제

이 장을 마치면
  • API 문서(요청 변수 표)를 보고 호출 주소를 직접 만들기
  • "Encoding 키 / Decoding 키" 함정을 설명하고 피하기
  • HTTP 상태 코드(게이트웨이)와 resultCode(서비스), 두 층의 에러를 구분해서 처리하기
  • 페이지 넘기기 · 재시도 · 시간 제한 · 트래픽 한도를 갖춘 수집기를 짜기
  • 받은 데이터를 "다시 돌려도 안전하게" 저장하기 (원본 보관 · 덮어쓰기 · 수집 시각)
  • 공공 API와 광고 매체 API의 인증 · 페이지 · 리포트 방식 차이 말하기

한 번의 호출이 거치는 길

주소창에 API 주소를 넣고 엔터를 치면, 1초도 안 되는 사이에 이런 일이 일어납니다.

순서일어나는 일여기서 나는 문제
1DNS: apis.data.go.kr를 IP 주소로 바꿈 (4장)회사망 · VPN에서 이름을 못 찾음
2TCP 연결 + TLS(https): 443번 문으로 연결, 암호화 약속방화벽 · 프록시 차단, 인증서 오류
3게이트웨이(문지기): 인증키가 있는지, 등록된 키인지, 오늘 한도가 남았는지 검사401 · 403 · 429 — 서비스까지 가지도 못함
4서비스(실제 기관 시스템): 요청 변수를 읽고 DB에서 찾음변수 오류, 데이터 없음 — 대개 200인데 본문에 실패
5응답: 상태 코드 + 헤더 + 본문(JSON 또는 XML)XML이 와서 JSON 해석 실패, 한글 깨짐
6내 코드: 해석 → 목록 꺼내기 → 다음 페이지 → 저장1건일 때 목록이 아님, 페이지 누락, 중복 저장

에러 메시지를 보면 먼저 "몇 번째 칸에서 막혔나"부터 정합니다. 이것만 해도 디버깅 시간이 반으로 줍니다(8장 "범위 좁히기").

공공데이터포털 사용 흐름

단계하는 일알아 둘 것
1. 찾기data.go.kr에서 "특일 정보" 검색 → 오픈 API 탭같은 데이터가 "파일 데이터"(CSV 내려받기)로도 있으면, 한 번만 쓸 거라면 파일이 더 쉬움
2. 활용 신청로그인 → "활용신청" → 목적 입력많은 API가 자동 승인. 개발계정은 하루 호출 한도가 있음 (API마다 다름, 상세 페이지에 적혀 있음)
3. 키 받기마이페이지 → 활용 신청 현황 → 일반 인증키화면에 따라 Encoding / Decoding 두 가지로 보임. 아래 인코딩 함정 필수
4. 기다리기승인 직후 바로 안 될 수 있음키가 각 기관 시스템까지 퍼지는 데 시간이 걸림. 직후의 "등록되지 않은 키"는 대개 잠시 뒤 해결
5. 문서 읽기상세 페이지의 요청 변수 · 출력 결과 표, 참고 문서(활용 가이드)요청 변수 이름이 API마다 다름 (_type=json / dataType=JSON / returnType=json)
6. 호출브라우저 → PowerShell · curl → 코드 순서로브라우저에서 먼저 성공시키면 코드 문제와 키 문제가 분리됨

요청 해부 — 주소 하나를 조각내기

https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo?serviceKey=...&solYear=2026&solMonth=05&_type=json
조각값뜻
schemehttps암호화해서 보냄. http도 되는 API가 많지만 키가 평문으로 흐름 → https 쓰기
hostapis.data.go.kr포털 공통 게이트웨이 (모든 기관 API의 입구)
path/B090041제공 기관 코드 (이 경우 한국천문연구원)
/openapi/service/SpcdeInfoService서비스 이름 (특일 정보)
/getRestDeInfo오퍼레이션 = "무엇을" (공휴일 조회). 같은 서비스에 getHoliDeInfo(국경일), get24DivisionsInfo(24절기) 등이 같이 있음
query?serviceKey=...인증키. 공공 API는 대부분 주소에 키를 넣음 (매체 API는 헤더)
&solYear=2026&solMonth=05요청 변수. 문서에 "필수"로 표시. 05처럼 두 자리를 요구하는 것이 흔함
&_type=json응답 형식. 안 넣으면 XML이 기본인 API가 많음
🧸 비유

host는 정부 종합청사 정문, 기관 코드는 건물 동, 서비스는 부서, 오퍼레이션은 창구 번호, 요청 변수는 신청서에 적는 칸, 인증키는 출입증입니다. 출입증이 없으면 정문(게이트웨이)에서 막히고, 신청서를 잘못 쓰면 창구(서비스)에서 반려됩니다.

REST일까?

주소에 getRestDeInfo라는 동사가 있고 거의 GET만 씁니다. 리처드슨 성숙도로 보면 1단계쯤이고, "HTTP + 주소 + JSON/XML"이라 흔히 REST API라고 부를 뿐입니다. 공공 API는 원래 SOAP·XML 시절에 만든 것이 많아서 그 흔적(XML 기본, header/body 봉투 구조)이 남아 있습니다.

인증키 인코딩 함정 — 가장 많이 막히는 곳

인증키에는 + / = 같은 문자가 들어 있습니다. 그런데 주소에서 이 문자들은 특별한 뜻이 있습니다(+는 공백, =는 "이름=값", /는 경로). 그래서 주소에 넣을 때는 퍼센트 인코딩을 합니다: + → %2B, / → %2F, = → %3D.

키모양 (예시)언제 쓰나
Decoding (원래 키)my+test/key==코드 라이브러리에 params로 넘길 때 (라이브러리가 알아서 인코딩)
Encoding (이미 인코딩된 키)my%2Btest%2Fkey%3D%3D주소 문자열을 손으로 이어 붙일 때 (브라우저 주소창 · curl)

함정은 Encoding 키를 라이브러리에 넘기는 것입니다. 라이브러리가 한 번 더 인코딩해서 %가 %25가 됩니다.

Encoding 키를 params로 → serviceKey=my%252Btest%252Fkey%253D%253D   ← 두 번 인코딩, 서버는 다른 키로 봄
Decoding 키를 params로 → serviceKey=my%2Btest%2Fkey%3D%3D            ← 정상

결과는 SERVICE_KEY_IS_NOT_REGISTERED_ERROR. 키는 맞는데 "등록되지 않은 키"라고 나와서 한참 헤매게 됩니다. 반대로 Decoding 키를 주소창에 그냥 붙이면 +가 공백으로 바뀌어 같은 에러가 납니다.

규칙 한 줄 사람이 주소를 이어 붙이면 Encoding 키, 프로그램이 params를 만들면 Decoding 키. "키 등록 안 됨" 에러가 나면 키를 의심하기 전에 이것부터 바꿔 봅니다.

응답 해부 — 봉투 구조와 세 가지 버릇

{
  "response": {
    "header": { "resultCode": "00", "resultMsg": "NORMAL SERVICE." },
    "body": {
      "items": { "item": [
        { "dateKind": "01", "dateName": "어린이날",     "isHoliday": "Y", "locdate": 20260505, "seq": 1 },
        { "dateKind": "01", "dateName": "부처님오신날", "isHoliday": "Y", "locdate": 20260524, "seq": 1 }
      ] },
      "numOfRows": 10, "pageNo": 1, "totalCount": 3
    }
  }
}
칸뜻
header.resultCode서비스의 성공/실패. "00"이 성공. HTTP 200이어도 여기가 실패일 수 있음
body.items.item실제 데이터 행들
numOfRows · pageNo한 페이지 크기 · 지금 페이지 (요청한 값이 그대로 돌아옴)
totalCount전체 건수. "다음 페이지가 있나"를 이걸로 계산

XML로 설계한 API를 JSON으로 바꿔 내보내는 곳이 많아서, 이런 버릇이 생깁니다.

  1. 1건이면 목록이 아니라 객체: "item": {...}. 여러 건이면 "item": [...]. 코드가 항상 목록이라고 믿으면 1건인 달에 터집니다.
  2. 0건이면 items가 빈 문자열: "items": "". items["item"]에서 터집니다.
  3. 숫자 · 날짜 모양이 제각각: locdate가 숫자 20260505로 옴(날짜형 아님). 앞의 0이 사라지는 코드값, 문자열 숫자 "1,234"도 흔합니다. 받은 그대로 저장하고 형 변환은 나중(dbt staging)에.

이 버릇들은 문서에 안 쓰여 있는 경우가 많습니다. 그래서 응답을 그대로 파일로 남겨 두는 습관이 중요합니다. 터졌을 때 그 파일을 열어 보면 바로 보입니다.

에러는 두 층 — 문지기와 창구

2026-11-19에 이 API를 키 없이, 그리고 틀린 키로 직접 불러 본 실제 응답입니다.

키 없음   → HTTP 401 Unauthorized
{ "OpenAPI_ServiceResponse": { "cmmMsgHeader": {
    "errMsg": "SERVICE_KEY_IS_NULL", "returnAuthMsg": "서비스 접근거부", "returnReasonCode": "20" } } }

틀린 키   → HTTP 403 Forbidden
{ "OpenAPI_ServiceResponse": { "cmmMsgHeader": {
    "errMsg": "SERVICE_KEY_IS_NOT_REGISTERED_ERROR", "returnAuthMsg": "등록되지 않은 서비스키", "returnReasonCode": "30" } } }

봉투 모양부터 다릅니다. 정상 응답은 response.header, 게이트웨이 에러는 OpenAPI_ServiceResponse.cmmMsgHeader입니다. 그래서 코드는 두 층을 따로 봐야 합니다.

층어떻게 알 수 있나흔한 코드코드에서 할 일
문지기 (게이트웨이)HTTP 상태 4xx · 5xx, cmmMsgHeader20 접근 거부(키 없음 · 미승인), 22 호출 한도 초과, 30 미등록 키, 31 활용 기간 만료, 32 미등록 IP키 · 한도 문제. 22는 내일까지 기다리거나 운영계정 신청. 나머지는 사람이 고쳐야 함 → 즉시 멈춤
창구 (서비스)HTTP 200인데 header.resultCode ≠ "00"03 데이터 없음, 10 잘못된 요청 변수, 11 필수 변수 누락, 12 없는 서비스, 01 · 02 · 99 서버 쪽 오류10 · 11은 내 요청을 고침. 03은 "0건"으로 처리할지 정함. 01 · 02 · 99는 재시도 후보
그 아래 (네트워크)시간 초과, 연결 끊김, 502 · 503 · 504잠깐 기다렸다 재시도

코드 번호는 포털 공통 표에 나오는 값입니다. 기관마다 몇 개가 다르거나 더 있을 수 있으니, 실제로는 각 API의 활용 가이드 문서 맨 뒤 "에러 코드" 표를 확인하세요. 예전에는 게이트웨이 에러도 HTTP 200 + XML로 주던 시절이 있어서, 오래된 블로그 글과 지금 응답이 다를 수 있습니다.

끝까지 모으기 — 수집기의 네 기둥

한 번 부르는 것과, 매일 빠짐없이 모으는 것은 다른 일입니다. 수집기는 네 가지를 갖춰야 합니다.

기둥왜어떻게
페이지 넘기기한 번에 최대 N건만 줌. 1페이지만 받으면 조용히 데이터가 빠짐pageNo × numOfRows ≥ totalCount가 될 때까지 반복. 끝나면 받은 건수 = totalCount인지 확인
시간 제한 (timeout)없으면 응답 없는 서버를 영원히 기다림. Airflow 작업이 몇 시간째 "running"모든 호출에 timeout=10 같은 값
재시도네트워크 · 서버 일시 오류는 흔함. 한 번 실패로 하루치 데이터를 버리면 안 됨일시 오류(429 · 5xx · 시간 초과)만 재시도. 1 · 2 · 4 · 8초처럼 점점 길게(지수 백오프). 4xx는 재시도 금지
속도 조절하루 한도 · 초당 한도. 너무 빨리 부르면 차단호출 사이에 잠깐 쉬기, 429 응답의 Retry-After 헤더 따르기
⚠ 재시도하면 안 되는 것

401 · 403 · 400(내 잘못)을 재시도하면 한도만 깎이고, 공공 API는 반복된 잘못된 호출로 차단될 수도 있습니다. 그리고 읽기(GET)는 재시도해도 안전하지만, 매체 API에서 예산 변경 같은 쓰기(POST)를 재시도하면 두 번 실행될 수 있습니다. 같은 요청을 여러 번 보내도 결과가 같은 성질을 멱등성이라고 합니다.

데이터 엔지니어처럼 저장하기

습관이유우리 프로젝트에서는
원본을 받은 그대로 보관 (raw JSON)해석 코드에 버그가 있어도 다시 부르지 않고 재처리. 이상한 응답을 나중에 증거로매체 원천 → BigQuery raw_* 테이블, 변환은 dbt
수집 시각 붙이기 (fetched_at)같은 날짜 데이터가 나중에 바뀌기도 함. 언제 받은 값인지 알아야 함매체 전환은 며칠 뒤까지 늘어남 → "최신 추출본이 이김" (연습용 Cube의 make_data.py가 이 규칙)
다시 돌려도 안전하게 (멱등)실패 후 다시 돌렸더니 데이터가 두 배가 되는 사고가 가장 흔함날짜 · 파티션 단위로 지우고 다시 쓰기 또는 MERGE. 덧붙이기(append)만 하지 않기
증분 + 되돌아보기매일 전체를 받으면 느리고 한도가 모자람. 그렇다고 어제치만 받으면 늦게 바뀐 값을 놓침"최근 7~30일을 매일 다시 받기" (기여 기간만큼). 공휴일처럼 안 바뀌는 데이터는 1년에 한 번
비밀은 코드 밖에키가 git에 올라가면 지워도 기록에 남음 (공개 저장소면 몇 분 안에 수집됨)환경 변수 · .env(gitignore) · Airflow Connection · Secret Manager
로그 남기기"어제 몇 건 받았지?"에 답할 수 있어야 함호출 수 · 건수 · 재시도 횟수 · 걸린 시간

공공 API vs 광고 매체 API

공휴일 API에서 배운 뼈대(인증 → 요청 → 페이지 → 에러 → 저장)는 같습니다. 달라지는 곳은 세 군데입니다.

1. 신분 확인(인증) 방식

방식모양쓰는 곳특징
주소에 키?serviceKey=...공공데이터포털, 많은 공개 API가장 쉬움. 대신 로그 · 기록에 키가 남음
헤더에 키X-API-KEY: ...많은 SaaS주소에 안 남아서 조금 더 안전
OAuth 2.0 토큰Authorization: Bearer ...Meta, Google Ads, GA4사람이 한 번 "허용"을 눌러 받은 토큰. 유효 기간이 있어 갱신(refresh token) 필요
서비스 계정 (JWT)키 파일로 서명 → 토큰 교환BigQuery, GCP 전반사람 없이 서버끼리. 키 파일 관리가 핵심

3. 큰 리포트는 "주문하고 나중에 받기"

공휴일처럼 작은 데이터는 바로 답이 옵니다. 광고 성과처럼 큰 리포트는 서버도 계산이 오래 걸려서 비동기 리포트를 씁니다: ① 리포트 만들어 달라고 요청(POST) → ② 작업 번호를 받음 → ③ "다 됐어?"를 몇 초마다 물음(폴링) → ④ 끝나면 결과 주소에서 받음. Meta의 비동기 인사이트, Naver의 대용량 리포트가 이 모양입니다. Google Ads는 검색 결과를 흘려보내는 스트리밍(gRPC)으로 큰 응답을 나눠 줍니다.

# 2026년 공휴일 수집기 - 표준 라이브러리만 사용 (pip 설치 불필요)
import csv, json, os, sys, time, urllib.error, urllib.parse, urllib.request
from datetime import datetime
from pathlib import Path

BASE = os.environ.get("HOLIDAY_BASE", "http://localhost:8010")      # 진짜: https://apis.data.go.kr
PATH = "/B090041/openapi/service/SpcdeInfoService/getRestDeInfo"
KEY = os.environ["DATA_GO_KR_KEY"]          # Decoding 키를 환경 변수로 (코드 · git 에 키를 쓰지 않음)
YEAR = sys.argv[1] if len(sys.argv) > 1 else "2026"
RAW = Path("raw") / f"holidays_{YEAR}"      # 받은 그대로 저장하는 곳
RAW.mkdir(parents=True, exist_ok=True)


def call(params, tries=4):
    """한 번 호출. 일시 오류(429 · 5xx · 네트워크)는 기다렸다 재시도, 내 잘못(4xx)은 바로 멈춤."""
    url = BASE + PATH + "?" + urllib.parse.urlencode(params)   # 여기서 키가 한 번 인코딩됨
    for i in range(tries):
        try:
            with urllib.request.urlopen(url, timeout=10) as r:
                return json.loads(r.read().decode("utf-8"))
        except urllib.error.HTTPError as e:
            body = e.read().decode("utf-8", "replace")
            if e.code == 429 or e.code >= 500:
                wait = 2 ** i                       # 1, 2, 4, 8초 (지수 백오프)
                print(f"  {e.code} 일시 오류, {wait}초 뒤 재시도")
                time.sleep(wait)
                continue
            raise SystemExit(f"{e.code} 요청 오류 - 재시도해도 소용없음: {body}")
        except urllib.error.URLError as e:
            print(f"  네트워크 오류 {e.reason}, 재시도")
            time.sleep(2 ** i)
    raise SystemExit("재시도를 다 썼음")


def items_of(data):
    """header 확인 + item 을 항상 목록으로."""
    header = data["response"]["header"]
    if header["resultCode"] != "00":                     # HTTP 200 이어도 실패일 수 있음
        raise SystemExit(f"서비스 오류 {header['resultCode']} {header['resultMsg']}")
    body = data["response"]["body"]
    items = body.get("items") or {}                      # 0건이면 "" 로 옴
    item = items.get("item", [])
    return (item if isinstance(item, list) else [item]), body["totalCount"]


rows = []
fetched_at = datetime.now().isoformat(timespec="seconds")
for m in range(1, 13):
    page = 1
    while True:
        params = {"serviceKey": KEY, "solYear": YEAR, "solMonth": f"{m:02d}",
                  "numOfRows": 2, "pageNo": page, "_type": "json"}   # 일부러 작게 - 페이지 넘김 연습
        data = call(params)
        (RAW / f"{m:02d}_p{page}.json").write_text(json.dumps(data, ensure_ascii=False), encoding="utf-8")
        got, total = items_of(data)
        rows += [{**it, "fetched_at": fetched_at} for it in got]
        print(f"{YEAR}-{m:02d} p{page}: {len(got)}건 (전체 {total})")
        if page * params["numOfRows"] >= total:
            break
        page += 1
        time.sleep(0.2)                                  # 예의상 천천히 (트래픽 한도)

out = Path(f"holidays_{YEAR}.csv")                       # 같은 해를 다시 돌리면 덮어씀 = 중복 없음
with out.open("w", newline="", encoding="utf-8-sig") as f:
    w = csv.DictWriter(f, fieldnames=["locdate", "dateName", "isHoliday", "dateKind", "seq", "fetched_at"])
    w.writeheader()
    w.writerows(rows)
print(f"완료: {out} {len(rows)}행")

# 공공데이터포털 '특일 정보' 흉내 서버 (연습용) - python mock_datagokr.py 로 실행, http://localhost:8010
import json
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import urlparse, parse_qs

KEY = "my+test/key=="          # 연습용 '진짜 키' (Decoding 모양)
# 연습용 목록 (실제 공휴일과 다를 수 있음 - 진짜는 4단계에서 포털로)
HOLIDAYS = [("20260101", "1월1일"), ("20260216", "설날"), ("20260217", "설날"), ("20260218", "설날"),
            ("20260301", "삼일절"), ("20260302", "대체공휴일"), ("20260505", "어린이날"),
            ("20260524", "부처님오신날"), ("20260525", "대체공휴일"), ("20260603", "전국동시지방선거"),
            ("20260606", "현충일"), ("20260815", "광복절"), ("20260817", "대체공휴일"),
            ("20260924", "추석"), ("20260925", "추석"), ("20260926", "추석"), ("20261003", "개천절"),
            ("20261005", "대체공휴일"), ("20261009", "한글날"), ("20261225", "기독탄신일")]
calls = {"n": 0}

class H(BaseHTTPRequestHandler):
    def send(self, code, obj):
        body = json.dumps(obj, ensure_ascii=False).encode("utf-8")
        self.send_response(code)
        self.send_header("Content-Type", "application/json;charset=UTF-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_GET(self):
        u = urlparse(self.path)
        q = {k: v[0] for k, v in parse_qs(u.query).items()}   # parse_qs 가 %2B -> + 로 한 번 풀어 줌
        if u.path != "/B090041/openapi/service/SpcdeInfoService/getRestDeInfo":
            return self.send(404, {"error": "no such path"})
        # 1층: 게이트웨이 - 키 검사 (실제 포털과 같은 모양)
        key = q.get("serviceKey") or q.get("ServiceKey")
        if not key:
            return self.send(401, {"OpenAPI_ServiceResponse": {"cmmMsgHeader": {
                "errMsg": "SERVICE_KEY_IS_NULL", "returnAuthMsg": "서비스 접근거부", "returnReasonCode": "20"}}})
        if key != KEY:
            return self.send(403, {"OpenAPI_ServiceResponse": {"cmmMsgHeader": {
                "errMsg": "SERVICE_KEY_IS_NOT_REGISTERED_ERROR", "returnAuthMsg": "등록되지 않은 서비스키", "returnReasonCode": "30"}}})
        # 가끔 일부러 실패 (재시도 연습)
        calls["n"] += 1
        if calls["n"] % 4 == 0:
            return self.send(503, {"error": "잠시 후 다시 시도"})
        # 2층: 서비스 - 요청 변수 검사
        year, month = q.get("solYear"), q.get("solMonth")
        if not year or not month or len(month) != 2:
            return self.send(200, {"response": {"header": {"resultCode": "10", "resultMsg": "INVALID_REQUEST_PARAMETER_ERROR"}}})
        rows = [{"dateKind": "01", "dateName": n, "isHoliday": "Y", "locdate": int(d), "seq": 1}
                for d, n in HOLIDAYS if d[:4] == year and d[4:6] == month]
        size, page = int(q.get("numOfRows", 10)), int(q.get("pageNo", 1))
        part = rows[(page - 1) * size: page * size]
        # XML 을 JSON 으로 바꾼 API 의 버릇: 0건이면 items 가 빈 문자열, 1건이면 item 이 목록이 아니라 객체
        items = "" if not part else {"item": part[0] if len(part) == 1 else part}
        self.send(200, {"response": {"header": {"resultCode": "00", "resultMsg": "NORMAL SERVICE."},
                                     "body": {"items": items, "numOfRows": size, "pageNo": page, "totalCount": len(rows)}}})

    def log_message(self, fmt, *args):
        print(self.command, self.path[:110], "->", args[1] if len(args) > 1 else "")

if __name__ == "__main__":
    print("모의 공공데이터포털: http://localhost:8010  (Ctrl+C 로 종료)")
    HTTPServer(("127.0.0.1", 8010), H).serve_forever()

퀴즈

파이썬에서 urlencode({"serviceKey": 키, ...})로 주소를 만든다. 어떤 키를 넣어야 하나?

  1. Encoding 키 — 주소에 들어가니까
  2. Decoding 키 — 라이브러리가 인코딩을 한 번 해 주니까
  3. 둘 다 된다
  4. 키를 Base64로 한 번 더 바꿔서
라이브러리가 인코딩을 하므로 원래 키(Decoding)를 넘깁니다. Encoding 키를 넘기면 %가 %25가 되는 이중 인코딩으로 "등록되지 않은 키"가 됩니다.

HTTP 200을 받았고 본문이 {"response":{"header":{"resultCode":"10", ...}}}이다. 맞는 해석은?

  1. 성공. 200이니까
  2. 게이트웨이에서 키가 막혔다
  3. 요청은 서비스까지 갔지만 요청 변수가 잘못됐다
  4. 서버가 다운됐으니 재시도한다
게이트웨이(문지기)는 통과했고 서비스(창구)가 요청 변수 오류(10)로 반려한 것입니다. 재시도해도 같은 결과이니 요청을 고쳐야 합니다.

12월에는 공휴일이 1건이다. for it in body["items"]["item"]: 코드가 12월에 이상하게 동작하는 이유는?

  1. 1건이면 item이 목록이 아니라 객체(딕셔너리)로 와서, 반복문이 행이 아니라 필드 이름을 돈다
  2. 12월은 numOfRows를 넘어서
  3. JSON이 아니라 CSV로 와서
  4. totalCount가 0이라서
XML을 JSON으로 바꾼 API의 흔한 버릇입니다. 딕셔너리를 for로 돌면 키(dateKind, dateName …)가 나옵니다. 항상 목록으로 감싸는 함수를 하나 둡니다.

재시도 전략으로 가장 알맞은 것은?

  1. 모든 에러를 1초 간격으로 100번 재시도
  2. 401 · 403도 키가 늦게 퍼질 수 있으니 무한 재시도
  3. 재시도는 위험하니 절대 안 함
  4. 429 · 5xx · 시간 초과만, 1 · 2 · 4 · 8초처럼 점점 길게 몇 번까지만
일시 오류만 재시도하고(내 잘못인 4xx는 바로 멈춤), 간격을 늘려 서버에 숨 돌릴 틈을 주며, 횟수에 상한을 둡니다. 이것이 지수 백오프입니다.

매일 아침 수집이 실패해서 오후에 다시 돌렸다. 데이터가 두 배가 되지 않으려면?

  1. 오후에는 돌리지 않는다
  2. 날짜(파티션) 단위로 기존 것을 지우고 다시 쓰거나 MERGE한다 — 멱등하게
  3. 끝에 덧붙인 뒤 SELECT DISTINCT로 본다
  4. API 호출 수를 줄인다
"다시 돌려도 결과가 같다"가 데이터 파이프라인의 기본 안전장치입니다. DISTINCT로 감추면 진짜 중복과 가짜 중복을 구분하지 못하게 됩니다.
