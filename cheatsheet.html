Airflow 3 명령

연습 환경에서는 컨테이너 안에서 실행합니다: docker exec -it 컨테이너이름 airflow ...

명령하는 일
airflow standalone스케줄러·API 서버·DAG 프로세서·메타DB를 한 번에 띄움 (연습용). 첫 실행 때 admin 비밀번호 출력
airflow version버전 확인
airflow dags list읽힌 DAG 목록
airflow dags list-import-errors문법 오류 등으로 못 읽은 DAG 파일과 오류 내용 — DAG가 안 보이면 이것부터
airflow dags test 내_dag 2026-10-05스케줄러 없이 DAG 한 번을 그 자리에서 실행 (디버깅용)
airflow tasks test 내_dag 태스크id 2026-10-05태스크 하나만 실행, 메타DB에 기록 안 남김
airflow dags trigger 내_dag지금 실행 요청 (스케줄러가 집어감). --conf '{"k":"v"}'
airflow dags pause / unpause 내_dag스케줄 멈추기 / 켜기
airflow backfill create --dag-id 내_dag --from-date 2026-10-01 --to-date 2026-10-05지난 기간 채우기 (3.x 문법). --reprocess-behavior failed, --max-active-runs 2
airflow dags list-runs 내_dag실행 기록 목록
airflow tasks states-for-dag-run 내_dag 런id한 실행 안의 태스크별 상태
airflow connections list / variables list저장된 접속 정보·변수
airflow config get-value core dags_folderDAG 폴더 위치 확인
2.x 와 다른 점

3.x에서는 airflow webserver 대신 airflow api-server, airflow dags backfill 대신 airflow backfill create, DAG 인자 schedule_interval 대신 schedule, Dataset 대신 Asset 입니다. 인터넷 예제가 2.x 문법인 경우가 많으니 확인하세요.

from pyspark.sql import functions as F 를 했다고 가정합니다. 모든 줄은 변환(계획만 쌓임)이고, 마지막 표의 것들이 액션(실제 실행)입니다.

LOWER(TRIM(status))F.lower(F.trim("status"))
CAST(d AS DATE)F.col("d").cast("date")
WHERE status = 'completed'df.where(F.col("status") == "completed") (filter도 같음)
